# AI verification instructions

Read README.md and skills.json before assigning or reviewing exercises.

1. Inspect the relevant AI-generated feature. Record concrete implementation problems and the transferable skills involved in its problems.md.
2. Maintain a granular skill map with stable, descriptive IDs. Do not mark a broad skill verified when evidence covers only one smaller part. Preserve existing skill IDs and all records in skills.json.
3. Before preparing each assignment, read skills.json and prior reviews. Classify each relevant skill as Verified, Target, or Unverified prerequisite. Treat a skill as Verified only when it has both an independent passing review and a matching record in skills.json. A previous assignment, exposure, or supplied starter implementation is not proof. Only then may AI automate that skill. Never automate a skill that lacks this evidence. Remove unverified prerequisites or teach them first.
4. Assign one new target skill per exercise by default. Combine targets only when the combination itself is the learning objective. Keep the exercise small, transferable, beginner-friendly, and focused on observable criteria for the target only.
5. Assume the user is a complete beginner unless they have verified evidence. Start with a tiny, low-setup exercise that changes or implements one observable thing. Increase difficulty gradually. Assign one exercise at a time. Future exercise descriptions may be outlined in the roadmap, but do not pre-create their starter files or assign them before reviewing the current work. Finalize each next exercise against the latest skills.json and review.md.
6. Clearly label AI-supplied code, what the user must implement, editable files/areas, provided infrastructure, and run/submit steps. Infrastructure outside the target skill earns no verification credit. Do not include the solution in starter code, comments, examples, or reference answers before submission.
7. Do not modify user-authored or in-progress work without explicit permission. If a replacement or fresh independent attempt is needed, create a new exercise/attempt folder and preserve the existing files.
8. The solutions/ folder may hold reference answers only after the user has completed and submitted that exercise. Do not supply implementation code or hints unless requested. If solution-level help is given, classify it as guided practice and require a fresh independent exercise before verification.
9. Review only the exercise's target skills against its stated criteria. Record pass/fail, evidence, specific learning gaps, date, and exercise type in review.md. Never mark an unsubmitted or unreviewed skill verified.
10. After an independent demonstrated pass, append an object to skills.json verifiedSkills with id, name, verifiedAt (YYYY-MM-DD), and evidence (relative path to the review). Preserve all existing records. If the user struggles, offer a smaller practice exercise for the same gap.
11. After each pass, offer the next appropriate unverified skill, automating verified parts where useful. Re-practice of verified skills is optional. Use occasional integration exercises only after component skills are verified, and label them separately from individual checks.
12. Track feature readiness separately from individual skill records. Individual passes do not by themselves prove the original feature is ready to merge; code review and testing are still required. Do not merge automatically.

The initial empty verifiedSkills array means no verification evidence has been recorded here; it does not mean the user lacks those skills.
