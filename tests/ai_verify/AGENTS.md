# AI verification instructions

After each change to a json/<tech>.json file, re-assess its `proficiency` (None, Beginner, Intermediate, Advanced) from the number and difficulty of verified skills, and keep `proficiencyNote` under 3 words.

Read README.md and every file in the json/ folder (css.json, html.json, js.json, react.json, ...) before assigning or reviewing exercises. The json/ folder is the only verification record; there is no single skills.json.

1. Inspect the relevant AI-generated feature. Record concrete implementation problems and the transferable skills involved in its problems.md.
2. Keep exercise targets granular and observable, but do not create a separate profile entry for every exercise or small skill. Maintain a concise set of broader capability entries in json/*.json. When a newly verified small skill belongs to an existing capability, update that entry's description and evidence rather than adding another block. Expand a capability only to include parts supported by verified evidence; create a separate entry only for a genuinely distinct area. Preserve stable IDs.
3. Before preparing each assignment, read all json/*.json files and prior reviews. Classify each relevant skill as Verified, Target, or Unverified prerequisite. Treat a skill as Verified only when it has both an independent passing review and a matching record in the json/ folder. A previous assignment, exposure, or supplied starter implementation is not proof. Only then may AI automate that skill. Never automate a skill that lacks this evidence. Remove unverified prerequisites or teach them first.
4. Assign one new target skill per exercise by default. Combine targets only when the combination itself is the learning objective. Keep every exercise as easy as possible: one tiny, dedicated, observable change. Each `exercise.md` contains only: title, Task, Skills needed, Skills this exercise verifies. No other sections or extra prose. In starter files, mark what the user must do with a `TODO` comment (never reveal the solution). The goal is a low-pressure record that lets the user automate the skill with AI, not to ask difficult questions or prove expertise. Do not add tricks, extra requirements, or stretch goals.
5. Assume the user is a complete beginner unless they have verified evidence. Start with a tiny, low-setup exercise that changes or implements one observable thing. Increase difficulty gradually. Assign one exercise at a time. Future exercise descriptions may be outlined in the roadmap, but do not pre-create their starter files or assign them before reviewing the current work. Finalize each next exercise against the latest json/*.json records and review.md.
6. Clearly label AI-supplied code, what the user must implement, editable files/areas, provided infrastructure, and run/submit steps. Infrastructure outside the target skill earns no verification credit. Do not include the solution in starter code, comments, examples, or reference answers before submission.
7. Do not modify user-authored or in-progress work without explicit permission. If a replacement or fresh independent attempt is needed, create a new exercise/attempt folder and preserve the existing files.
8. The solutions/ folder may hold reference answers only after the user has completed and submitted that exercise. Do not supply implementation code or hints unless requested. If solution-level help is given, classify it as guided practice and require a fresh independent exercise before verification.
9. Review only the exercise's target skills against its stated criteria. Record pass/fail, evidence, specific learning gaps, date, and exercise type in review.md. Never mark an unsubmitted or unreviewed skill verified.
10. After an independent demonstrated pass, update verifiedSkills in the JSON file for the skill's technology (json/css.json, json/js.json, json/html.json, json/react.json; create json/<tech>.json with the same shape if missing). Add the new evidence to the existing broader capability entry when it belongs there; do not make a new block for each exercise. Create a new profile entry only for a genuinely distinct capability. Keep evidence for all verified parts and do not imply unverified parts are verified. Preserve stable IDs. If the user struggles, offer a smaller practice exercise for the same gap.
11. After each pass, offer the next appropriate unverified skill, automating verified parts where useful. Re-practice of verified skills is optional. Use occasional integration exercises only after component skills are verified, and label them separately from individual checks.
12. Merge policy: no feature from the AI branch may be merged into main unless every skill it requires has a matching record in the json/ folder. Missing records block the merge. Individual passes alone do not make a feature ready; code review and testing are still required. Do not merge automatically.

The initial empty verifiedSkills array means no verification evidence has been recorded here; it does not mean the user lacks those skills.

## Starter snapshots

For each new exercise, create an original/ folder containing a runnable, unchanged snapshot of the supplied starter files before the user begins. Keep relative file links working inside it. Preserve this snapshot during later attempts and reviews; user work belongs outside original/.
